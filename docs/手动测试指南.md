# omem V0.2 手动测试指南

> 目标读者：开发者本人。
> 本文是 **CLI 全量手工测试**。只关心「记忆可信度怎么测、怎么用终端 Agent（Cursor / CodeBuddy）核实」请直接看姊妹篇 `docs/记忆可信度的人工核实与Agent协作手册.md`。
> 全部命令在 `X:/omem` 项目根执行；文中 `node bin/omem.js` 可替换为全局命令 `omem`（见 §1 路径 B）。
> §3 的脚本是 Git Bash 语法。Windows 上请打开 Git Bash，不要用 WSL 的 `bash`（那里通常没有 Windows 的 `node`）。PowerShell 只适合 §2 那种逐条设环境变量的写法。

> **V0.2 变化速查**（与 V0.1 手册的差异）：
> - 命令面从 20 条收敛到 **13 条**：`init install sync skip add search review topics verify backup profile redact serve`。删掉的有 `gc`（并入 `review --gc`）、`context`、`snapshot`（并入 `backup`）、`audit`、`eval`、`api`、`rebuild`（改名 `verify`）、`topic`（改 `topics`）。
> - **没有数据库了**：索引是从 Markdown 派生的内存视图，每次进程启动重建。没有 `index/omem.db`，也没有 FTS5。
> - **topic 即身份即文件名**：`knowledge/<domain>/<topic>.md`。`omem add` 必须带 `--topic`；同 topic 再写就是覆盖同一份活文档（git 留历史）。
> - **没有 `verified` 字段**：信任只有 `confidence` 一个数字（0.35 / 0.55 / +印证加成 / 0.80 自动上限 / 0.90 人工过目）。
> - `--tier rules` 已移除（退出码 1）；主题级审阅策略（`review.toml`）已移除。

## 1. 测试路径决策：打包 vs 直接跑

| 路径 | 命令 | 适用场景 | 说明 |
|---|---|---|---|
| **A. 项目内直接跑**（日常主用） | `npm run build` 后 `node bin/omem.js <cmd>` | 开发循环、改完即测 | `dist/` 是发布产物，改完 `src/` 记得先 build |
| **B. npm link** | `npm link` → 任意目录执行 `omem <cmd>` | 验证"全局安装后"的真实体验 | 同时验证 npm bin shim 与 `files` 字段；`npm unlink -g omem` 撤销 |
| **C. npm pack 打 tarball** | `npm pack` → `npm install -g omem-0.2.0-beta.1.tgz` | 发布前产物验证 | 验证 tarball 内容完整性（dist/bin 是否打进）；`prepublishOnly` 会先自动 build + test |
| **D. 自动化套件** | `npm test` / `npm run smoke` | 每次改动的回归底线 | 当前单测 **691 例（69 个文件）**，冒烟 **75 项**。计数会随用例增加，以命令收尾的通过数为准。冒烟含 MCP 裸 JSON-RPC 探针与 stdout 纯净断言 |
| **E. 本机只读验证** | `npm run test:live` | 本机已装 Claude Code、WorkBuddy、Cursor 时 | 先 build。只读复制会话到临时目录，加工结果也在临时目录，结束即删。不写 `~/.claude`、`~/.workbuddy`、`~/.cursor`、`~/.omem` |

**建议节奏**：改动用 A 快速迭代 → 提交前跑 D 全量 → 动到采集或 MCP 接线时再跑 E → 每个里程碑用 B/C 做一次"干净环境"验证。

环境要求：Node ≥ 22.5。检查：`node --version`。

Windows 上 `npm run smoke` 走的是 PATH 里的 `bash`。若该 `bash` 是 WSL，会报 `node: command not found`。改用：

```bash
"C:\Program Files\Git\bin\bash.exe" tests/smoke.sh
```

## 2. 铁律：隔离 OMEM_HOME

omem 的数据目录由 `OMEM_HOME` 决定（默认 `~/.omem`）。**测试一律指向一次性目录**，不要直接拿真实 `~/.omem` 做实验：

```bash
# Git Bash
export OMEM_HOME=/tmp/omem-t1

# PowerShell
$env:OMEM_HOME="C:\Users\wei\omem-t1"
```

- `omem init` 只建库和 git 数据仓，不扫描会话；删目录即完全重置，无残留。
- `omem sync` 只读扫描九个采集器，不改对方的会话文件：Claude Code（`~/.claude/projects`）、WorkBuddy（`~/.workbuddy/projects`）、Cursor（`~/.cursor/projects/<id>/agent-transcripts/<uuid>/<uuid>.jsonl`，不读 `subagents/`）、千问办公 QwenWork（`~/.qwenworkcn/projects`）、豆包办公 Doubao（Windows 默认 `%LOCALAPPDATA%/Doubao/User Data/Default/.doubao/agent_mode/workspace/.sessions/<sid>/agents/<agent>/system/trajectory.jsonl`，同一 session 下多 agent 只收 mtime 最新的 trajectory）、DeepSeek Harness（跨 `~/.dsh/sessions/<project>/<sid>/session{.v4}.jsonl.zstd` 解压的类型化 JSONL，用 `@toondepauw/node-zstd` 预编译二进制解压）、Qoder IDE（跨 `~/.qoder/cache/projects/<project>/conversation-history/<cid>/<cid>.jsonl` 与 `~/.qoder-cn/...` 双根，纯文本 OpenAI-messages 风格 JSONL，user 消息内嵌 `<user_query>` / `<attached_files>` / `<system-reminder>` 等噪声需逐层剥离）、CatPaw（`~/.catpaw/projects/<project>/<session>/agent-transcripts/transcript.txt`，纯文本格式，user 消息在 `<user_query>` 标签内、`assistant:` 后是回复，`[Thinking]`/`[Tool call]`/`[Tool result]` 为脚手架应跳过）、CodeBuddy（`~/.codebuddy/projects/<encoded-cwd>/<sid>.jsonl` 与 `~/.codebuddycn/...` 双根，JSONL 行格式同 WorkBuddy，但 `timestamp` 是毫秒数字，且会话行里没有 `cwd`——项目路径靠目录名反解，编码有损（`boss-sql` 与 `boss\sql` 无法区分），需靠文件系统确认目录真实存在才认）。对应环境变量 `OMEM_CLAUDE_PROJECTS`、`OMEM_WORKBUDDY_PROJECTS`、`OMEM_CURSOR_PROJECTS`、`OMEM_QWENWORK_PROJECTS`、`OMEM_DOUBAO_PROJECTS`、`OMEM_DEEPSEEK_PROJECTS`、`OMEM_QODER_PROJECTS`、`OMEM_QODER_CN_PROJECTS`、`OMEM_CATPAW_PROJECTS`、`OMEM_CODEBUDDY_PROJECTS`、`OMEM_CODEBUDDY_CN_PROJECTS`。`--collectors cursor,qwenwork` 只扫点名的。默认把剥掉系统包装后的 user/assistant 对话写入当前 `OMEM_HOME/sessions/`，并写 `PROCESS.md`。不写 `knowledge/`。`omem sync --tier rules` 已移除，会退出码 1。旧规则碎片用 `omem redact --source rules --yes` 批量硬删（不加 `--yes` 只预览条数与样例，不删任何文件）。`omem search` 只查结论；`omem search --sessions` 查原文。
- 用完即删：`rm -rf $OMEM_HOME`（Git Bash）或 `Remove-Item -Recurse -Force`（PowerShell）。

## 3. 十五分钟冒烟脚本（按序执行）

每步给出预期。任一步不符，先看 §6 排障。本节命令在 Git Bash 里整段执行。

```bash
export OMEM_HOME=/tmp/omem-t1 && cd /x/omem

# 采集隔离：把每个采集器的会话根指向空目录，冒烟就不会读到你本机的真实会话。
# 不做这一步，omem sync 会去扫 ~/.claude、~/.catpaw 等真实目录。
export OMEM_CLAUDE_PROJECTS=/x/omem/tests/fixtures/claude-projects
export OMEM_WORKBUDDY_PROJECTS=/tmp/omem-t1/empty
export OMEM_CURSOR_PROJECTS=/tmp/omem-t1/empty
export OMEM_QWENWORK_PROJECTS=/tmp/omem-t1/empty
export OMEM_DOUBAO_PROJECTS=/tmp/omem-t1/empty
export OMEM_DEEPSEEK_PROJECTS=/tmp/omem-t1/empty
export OMEM_QODER_PROJECTS=/tmp/omem-t1/empty
export OMEM_QODER_CN_PROJECTS=/tmp/omem-t1/empty
export OMEM_CATPAW_PROJECTS=/tmp/omem-t1/empty
export OMEM_CODEBUDDY_PROJECTS=/tmp/omem-t1/empty
export OMEM_CODEBUDDY_CN_PROJECTS=/tmp/omem-t1/empty
mkdir -p /tmp/omem-t1/empty

# S1 建库（不扫描会话；--no-scan 仍可传，效果与不传相同）
node bin/omem.js init --no-scan
# 预期：打印「omem data directory」+「git data repo initialized」+ Next 里的 omem sync；退出码 0
# 产物：$OMEM_HOME/{knowledge,archive,sessions,snapshots,logs,config.toml,MEMORY-INDEX.md,.git}
# 没有 index/ 目录了（B 阶段去掉了 SQLite）。

# S2 手动写入（topic 必填）
node bin/omem.js add "以后部署统一用 Docker Compose，不再裸跑 docker run" --topic deploy-compose --type preference --domain ops
# 预期：打印「Saved topic: deploy-compose」+「File: <path>」；退出码 0
node bin/omem.js add "随手记一条"
# 预期：退出码 1，提示必须给 --topic（topic 就是身份，不是可选元数据）

# S3 检索（子串匹配，没有 3 字符门槛）
node bin/omem.js search "Docker Compose"   # 两个词都要出现（AND）
node bin/omem.js search "部署"             # 单个词，子串匹配
node bin/omem.js search "不存在的词xyz"    # 无命中：退出码 0
# 命中时：行内带「· topic `deploy-compose` · confidence 0.9」和时效标注「— recorded just now, not reviewed」
# 无命中时打印「No memories found matching "…".」并附带 --all 的提示
# 断言技巧：零结果文案会回显查询词，断言时要用「正文里才有、查询里没有」的词

# S4 队列与生命周期
node bin/omem.js review                # 预期：「Queue is empty.」
node bin/omem.js review --gc --days 1  # 预期：扫描 N 条，标记 stale 0 条（只标记，未删除）

# S5 加工会话（合成 fixture，不碰真实数据）
# 默认档只把对话写入 sessions/ 并打印 PROCESS.md，不写 knowledge
OMEM_CLAUDE_PROJECTS=/x/omem/tests/fixtures/claude-projects node bin/omem.js sync --dry-run
# 预期：Processing complete (tier agent, dry-run)；dry-run 不落盘
OMEM_CLAUDE_PROJECTS=/x/omem/tests/fixtures/claude-projects node bin/omem.js sync
# 落盘后：sessions/ 有该会话，正文里密钥已打码；knowledge 不会新增 source: rules
node bin/omem.js sync --tier rules      # 预期：退出码 1（规则抽取已移除）

# S6 主题词表与重建
node bin/omem.js topics list
# 预期：「1 topic(s) · 1 living document(s)」+ 表头 TOPIC / CONF / LAST / TITLE
node bin/omem.js verify
# 预期：「Index fully rebuilt: N entries (in-memory index, derived from markdown)」+「MEMORY-INDEX.md regenerated: …」
#       +「Confidence check: N checked / M skipped」——账本复算，只报告差异，不改写文件

# S7 备份状态
node bin/omem.js backup status
# 预期：
#   Backend: git
#   Remote: （未配置：omem backup remote <url>）
#   Ahead: N · Behind: 0 · Uncommitted: M    （M≥1，因为 S2/S5 的文件还没提交）
```

### 退出码契约（规格 §7）

| 码 | 含义 | 复现 |
|---|---|---|
| 0 | 成功（含"冲突已处理"） | 上述全部命令 |
| 1 | 用法错误 | `node bin/omem.js redact`（缺 `--topic`/`--source`）；`omem add "x"`（缺 `--topic`）；`omem sync --tier rules` |
| 2 | 后端不可用 / 策略拒绝 | `omem profile use work` 后 `omem backup`；或把后端改成 webdav 后再 `omem backup`（见 §5） |

## 4. 分主题深测

### 4.1 md 权威性（第一卖点，优先验证）

写入路径默认**各留一笔本地提交**（配置项 `auto_commit`，默认 `session`）：`omem add` / `save_memory` 每落一条结论就一个 commit，逐条看 diff 比看一个大 commit 舒服；改成 `off` 可关掉。`omem init` 成功时最多有一条 `chore: omem init`（空仓库允许这次提交失败）。`omem sync`（采集）只改工作区。`omem backup` 才把未提交改动收成提交；没配远端时也会本地提交，并提示未配置远端。

```bash
rm -f $OMEM_HOME/MEMORY-INDEX.md          # 热层删掉
node bin/omem.js search "Docker Compose"  # 预期：仍能检索（内存索引从 md 现建）
node bin/omem.js verify                   # 预期：从 md 全量重建，条目数不变，MEMORY-INDEX.md 重新生成
node bin/omem.js sync                     # 无远端：本地提交，退出码 0
cd $OMEM_HOME && git log --oneline | head # 预期：能看到 omem: sync … 这一笔提交
```

再用 Obsidian/VSCode 打开 `$OMEM_HOME/knowledge` 改一条 md 的正文 → 跑 `omem search` → 改动生效（每次调用都 stat 活文档，mtime 变了就重读）。

### 4.2 检索矩阵

默认最多返回 `top_k`（配置里是 3）条。`archived` 默认不出现，`--all` 才带回。排序：命中词数 → 置信度（stale 降权 ×0.5）→ `last_confirmed`。

| 查询 | 路径 | 预期 |
|---|---|---|
| `Docker Compose` | 逐词 AND 子串 | 两个词都出现才命中 |
| `部署`（2 字中文） | 子串匹配 | 命中（**没有 3 字符门槛**，B 阶段去掉了 FTS5 trigram） |
| `Compose 部署` | 逐词 AND 子串 | 两词都出现就返回（词之间不需要相邻） |
| `search "部署" --domain ops` | 过滤 | 只返回 ops 域 |
| stale 降权 | 排序 | 手工把某条 `last_confirmed` 改到 200 天前 + `omem review --gc --days 1` → 该条排后，标注「not reviewed (cooled)」 |
| 归档 | 默认排除 | `omem review --dismiss <topic>` 后默认 search 找不到；`--all` 能找到，并带「— archived」 |

### 4.3 同步（本地 bare remote，不碰公网）

两边各 `add` 一条新记忆**不会**冲突：topic 不同，文件路径不同，git 会把两边都收进来。冲突只发生在**同一个文件**两边都改过的时候。

```bash
git init --bare -b main /tmp/omem-remote.git
node bin/omem.js backup remote /tmp/omem-remote.git
node bin/omem.js add "同步测试条目" --topic sync-test && node bin/omem.js backup     # 本地提交并 push

# 第二台「机器」。clone 出来的目录还不是 omem init 的骨架，测 pull 前先让它成为 OMEM_HOME：
git clone /tmp/omem-remote.git /tmp/omem-home2
# 在 home2 里改同一条 md 的正文并保留不提交；回到第一台改同一文件、backup 推上去；
# 再在 home2：OMEM_HOME=/tmp/omem-home2 node bin/omem.js backup
# 预期：退出码 0，报告冲突；远端版另存 <file>.conflict.md，本地版保留（只报告，不自动合并）
```

git 操作全在 `omem backup` 下（`remote` / `status` / `use` / `pull` / `push`）。`omem sync` 只做会话采集，带 git 子命令会以用法错误退出码 1。

### 4.4 MCP 接线（真实使用路径）

探针和加工都吃当前 `OMEM_HOME`。默认 `omem sync` 不会把 fixture 抽成结论。探针里的 `search_memory` 要命中「手写 SQL」，先对这个临时库 `omem add` 一条。探针还会往该库第一条记忆末尾追加一行标记，所以只能对临时库跑。

```bash
# 1) 只读预览（不落盘、不备份）
node bin/omem.js install --list
node bin/omem.js install --print-config workbuddy
node bin/omem.js install --print-config claude-code
# claude-code 的目标文件是 ~/.claude.json（merge mcpServers.omem），不是 ~/.claude/mcp.json
# workbuddy 的目标文件是 ~/.workbuddy/mcp.json
# cursor 的目标文件是 ~/.cursor/mcp.json（项目级 .cursor/mcp.json 另说，install 写的是用户目录这份）
# qwenwork 没有可写配置文件：--print-config qwenwork 打印应用内添加指引（设置 → 连接器 → 自定义 MCP），
#   install --target qwenwork 同样只打印指引，不写任何文件
# 预览应含 mcpServers.omem，且原有服务器键还在

# 2) 探针自检（必须把 bin 传进去；沿用上面的隔离 OMEM_HOME）
node tests/mcp-probe.mjs bin/omem.js
# 握手、tools/list、search_memory、save_memory 两次（第二次幂等）、外部编辑 catch-up、stdout 纯 JSON

# 3) 真实接线才会写文件。会话 jsonl 不动，但会改客户端配置：
#    - 只 merge 该客户端的 omem 键，写前自动备份为 <file>.omem-backup-<时间>
#    - marker 段（~/.claude/CLAUDE.md）仅在选中 claude-code 时写入
#    - 无 --target 时：TTY 进入交互勾选；非 TTY 直接报用法错误（不再静默全装），
#      脚本化场景必须显式 --target
#    未做全局安装时，写入的启动命令是「omem」。客户端会找不到它。
#    先 npm link，或 install --command 指到本机可执行文件。
cp ~/.workbuddy/mcp.json ~/.workbuddy/mcp.json.mybackup
node bin/omem.js install --target workbuddy

# 3b) 交互路径手测（需真实终端，无法脚本化）：直接跑 node bin/omem.js install
#    预期：列出全部客户端，光标在首行，cursor/workbuddy 预选中（detected + 路径已核实）
#    空格切换当前项 / a 全选 / n 全不选 / ↑↓ 移动 / 回车确认 / q 取消
#    q 或「回车但未选任何项」→ 不写任何文件；Ctrl+C 同样安全退出（raw mode 已恢复）
#    末项 "other" 选中后只打印通用 mcpServers 片段，不写文件

# 3c) codex 走 TOML 文本级合并：只追加/替换 [mcp_servers.omem]，
#    config.toml 里带引号的段名（[projects.'E:\x']）与空表段必须原样保留
node bin/omem.js install --print-config codex | head -1   # 预期：# Target file: …（不是 Cannot auto-generate）

# 4) 重启 WorkBuddy → 新对话里让 agent「检索一下我的 omem 记忆」
```

新 MCP 服务不会自动激活，必须重启客户端。交互会话与自动化会话的连接器开关相互独立。

### 4.5 安全基线

脱敏要求 `sk-ant-` 后面至少 20 个字符。`sk-ant-abc123` 太短，会原样入库，不能拿来当反例。

```bash
node bin/omem.js add "测试密钥 sk-ant-abc123def456ghi789jkl012 不要外泄" --topic key-leak-test --type fact
# 预期先打印「redacted 1 secret(s)」，再打印已保存
grep -r "sk-ant-abc123def456ghi789jkl012" $OMEM_HOME/knowledge    # 预期：无命中
grep -r "sk-ant-\*\*\*REDACTED\*\*\*" $OMEM_HOME/knowledge       # 预期：有打码标记

node bin/omem.js profile use work
node bin/omem.js backup                  # 预期：被拒，退出码 2
OMEM_ALLOW_WORK_EXPORT=1 node bin/omem.js backup   # 显式放行
node bin/omem.js profile use home        # 测完切回来，避免后面的 sync 被拒
```

`--force` 只绕过代码密度与长度上限，不绕过脱敏，也不绕过去重。

### 4.6 浏览器审阅（`review --ui`）

前置：队列里至少 3 条未过目条目（`omem review` 能看到）。全程用隔离 `OMEM_HOME`。

```bash
node bin/omem.js review --ui --no-open
# 预期：
#   Review UI is ready at http://127.0.0.1:<port>/?token=<hex>
#   Press Enter to open it in your browser, Ctrl+C to cancel. (non-interactive: continuing without waiting)
#   --no-open: open this URL yourself:
#   Waiting for your decisions in the browser… (timeout 10m)
# Ctrl+C 或超时：打印 Timed out / Cancelled，knowledge/ 下无任何改动
```

浏览器里按顺序验证：

1. 打开打印出来的 URL。左栏是队列，右栏是提示文字。
2. 点第一条：右栏出现正文、Evidence、Source sessions。**这一步同时把该条记为「已阅」**。
3. 点行首方框循环：✓ 确认 → ✕ 归档 → − 冷却 → 空。顶部统计跟随变化。
4. 再勾几条**不点开详情**的条目。
5. 点 Apply → 出现「N confirm (M unread will be assent)」确认条 → 点 Yes。

终端预期：

```
Snapshot: <home>/snapshots/<date>
  confirm  <已展开的 topic>  reviewed
  assent   <未展开的 topic>  0.8
Applied 2 · skipped 0 · missing 0.
```

落盘核对（**D2：没有 `verified` 字段了**）：

```bash
grep -h "^confidence:\|^confirmations:" "$OMEM_HOME"/knowledge/*/<已展开的 topic>.md   # 0.9 / 1
grep -h "^confidence:\|^confirmations:" "$OMEM_HOME"/knowledge/*/<未展开的 topic>.md   # 0.8 / 0
grep -l "^tags:.*assent" "$OMEM_HOME"/knowledge/*/*.md                                # 只有未展开的那条
```

边界：

- 重复点 Apply → 服务端 409，不会二次写入（`confirmations` 只加一次）
- 关掉终端等于 token 失效：页面刷新会连不上，这是设计不是 bug
- 会话标题解析慢的话，把 `src/web/review-data.ts` 的 `resolveSessionTitles` 调用去掉即可，队列与分级落章不依赖它

### 4.7 主题可见性与护栏

topic 就是身份，就是文件名（`knowledge/<domain>/<topic>.md`），所以文件名本身就是可见的。

```bash
node bin/omem.js topics list
# 预期：`N topic(s) · N living document(s)`，表头 TOPIC / CONF / LAST / TITLE
node bin/omem.js topics rename old-topic new-topic --dry-run
# 预期：打印将要移动的路径，不落盘
node bin/omem.js search "<命中某条带 topic 条目的词>"
# 预期：命中行的 `#fact #coding` 之后有 `· topic `xxx``
```

写入侧的告警（都会照常写入，只提示）：

```bash
# 近似主题：与既有主题互为前缀 / 去分隔符相同
node bin/omem.js add "内容" --topic <既有主题的前缀>
# 预期：Note: Topic "..." is close to existing "..."
```

词表：

```bash
tail -20 "$OMEM_HOME/PROCESS.md"
# 预期：两段结构——
#   `## Projects`（要干的活，按项目指纹分组，组标题是 `### <项目指纹>`）
#   `## Topics`（词表，逐行 `- `topic`  0.90 · 2026-10-19 · project local:abc123`）
```

**没有主题级审阅策略了**（D5）：`review.toml`、`omem topics policy`、`src/core/review-policy.ts` 全部删除。`omem review` 的队列只按「未过目 + 在 14 天窗口内或低置信」收，没有第二条静默通道。

## 5. 已知边界（不是缺陷）

- 检索没有倒排索引：内存线性扫描 + 暴力子串 AND。语料量级下 1–2ms，但**词多就会互相拖累**——一个冷僻词能让整条查询落空。
- `omem backup use webdav`（`dir` 同样）**退出码是 0**，并且会把 `config.toml` 里的 backend 改成 webdav。它只打印「V0.2 交付」。接下来的 `omem backup` 才会因后端未交付退出 2。测完执行 `omem backup use git` 改回来。
- 时间衰减 V0.2 不做。`omem review --gc` 只按 `stale_after_days`（默认 180）把条目标成 stale，不删任何东西。
- 置信度不随时间衰减：`confidence` 只在写入时按证据算，之后只可能被人过目提到 0.9。
- 规则抽取（`--tier rules`）已移除，`omem eval` 也已移除。质量评估暂时靠 `omem review` 的人工队列。

## 6. 排障速查

| 现象 | 大概率原因 |
|---|---|
| `ERR_UNSUPPORTED_ESM_URL_SCHEME` | 直接 `node dist/cli.js`；用 `node bin/omem.js` |
| `node: command not found`（跑 smoke 时） | PATH 上的 `bash` 是 WSL；改用 Git Bash，见 §1 |
| 「not initialized: … does not exist」 | 漏了 `export OMEM_HOME=...` 或目录被删；`omem init` 重建 |
| `omem add` 退出码 1 | 没带 `--topic`（topic 就是身份）；或正文太短/代码密度过高（可 `--force`） |
| 检索结果为空但明明 add 过 | 查询里某个词正文里没有（子串 AND）；或条目已归档，加 `--all` |
| `mcp-probe` 立刻打印用法并退出 | 没传 bin：`node tests/mcp-probe.mjs bin/omem.js` |
| 探针里 search 没命中「手写」 | 默认 `omem sync` 只写 sessions/，不会把 fixture 抽成结论。探针要命中，得先对这个临时库 `omem add` 一条含「手写 SQL」的记忆 |
| `omem install` 后客户端不显示工具 | 未重启客户端；连接器开关被关；或写入的命令是 `omem` 但没有全局安装 |
| `omem backup` 退出码 2 且提示 webdav 尚未交付 | 之前 `omem backup use webdav` 改过配置；`omem backup use git` |
| push 失败 | 无远端或网络；`omem backup status` 看 ahead/behind，本地提交不丢 |
| 写进去的条目搜不到 | 确认 `knowledge/<domain>/<topic>.md` 在（不是 `archive/`）；`omem verify` 看索引条数 |
