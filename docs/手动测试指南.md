# omem V0.1 手动测试指南

> 目标读者：开发者本人（V0.1 用户群边界见评估报告 4.9）。
> 本文是 **CLI 全量手工测试**。只关心「记忆可信度怎么测、怎么用终端 Agent（Cursor / CodeBuddy）核实」请直接看姊妹篇 `docs/记忆可信度的人工核实与Agent协作手册.md`。
> 全部命令在 `X:/omem` 项目根执行；文中 `node bin/omem.js` 可替换为全局命令 `omem`（见 §1 路径 B）。
> §3 的脚本是 Git Bash 语法。Windows 上请打开 Git Bash，不要用 WSL 的 `bash`（那里通常没有 Windows 的 `node`）。PowerShell 只适合 §2 那种逐条设环境变量的写法。

## 1. 测试路径决策：打包 vs 直接跑

| 路径 | 命令 | 适用场景 | 说明 |
|---|---|---|---|
| **A. 项目内直接跑**（日常主用） | `npm run build` 后 `node bin/omem.js <cmd>` | 开发循环、改完即测 | bin 包装器自动注入 `--experimental-sqlite`，无需手动带 flag |
| **B. npm link** | `npm link` → 任意目录执行 `omem <cmd>` | 验证"全局安装后"的真实体验 | 同时验证 npm bin shim + flag 自注入 + `files` 字段；`npm unlink -g omem` 撤销 |
| **C. npm pack 打 tarball** | `npm pack` → `npm install -g omem-0.1.0.tgz` | 发布前产物验证 | 验证 tarball 内容完整性（dist/bin 是否打进）；`prepublishOnly` 会先自动 build |
| **D. 自动化套件** | `npm test` / `npm run smoke` | 每次改动的回归底线 | 当前单测 153 例（20 个文件），冒烟 53 项。计数会随用例增加，以命令收尾的通过数为准。冒烟含 MCP 裸 JSON-RPC 探针与 stdout 纯净断言 |
| **E. 本机只读验证** | `npm run test:live` | 本机已装 Claude Code、WorkBuddy、Cursor 时 | 先 build。只读复制会话到临时目录，加工结果也在临时目录，结束即删。不写 `~/.claude`、`~/.workbuddy`、`~/.cursor`、`~/.omem` |

**建议节奏**：改动用 A 快速迭代 → 提交前跑 D 全量 → 动到采集或 MCP 接线时再跑 E → 每个里程碑用 B/C 做一次"干净环境"验证。

环境要求：Node ≥ 22.5（`node:sqlite` 内建 FTS5）。检查：`node --version`。

Windows 上 `npm run smoke` 走的是 PATH 里的 `bash`。若该 `bash` 是 WSL，会报 `node: command not found`。改用：

```bash
"C:\Program Files\Git\bin\bash.exe" tests/smoke.sh
```

## 2. 铁律：隔离 OMEM_HOME

omem 的数据目录由 `OMEM_HOME` 决定（默认 `~/.omem`）。**测试一律指向一次性目录**，不要直接拿真实 `~/.omem` 做实验：

```bash
# Git Bash
export OMEM_HOME=/tmp/omem-t1

# PowerShell
$env:OMEM_HOME="C:\Users\wei\omem-t1"
```

- `omem init` 会在 OMEM_HOME 建 git 数据仓；删目录即完全重置，无残留。
- `omem run` 只读扫描三个采集器，不改对方的会话文件：Claude Code（`~/.claude/projects`）、WorkBuddy（`~/.workbuddy/projects`）、Cursor（`~/.cursor/projects/<id>/agent-transcripts/<uuid>/<uuid>.jsonl`，不读 `subagents/`）。对应环境变量是 `OMEM_CLAUDE_PROJECTS`、`OMEM_WORKBUDDY_PROJECTS`、`OMEM_CURSOR_PROJECTS`。默认把剥掉系统包装后的 user/assistant 对话写入当前 `OMEM_HOME/sessions/`，并写 `PROCESS.md`。不写 `knowledge/`。规则片段要显式 `omem run --tier rules`。`omem search` 只查结论；`omem search --sessions` 查原文。
- 用完即删：`rm -rf $OMEM_HOME`（Git Bash）或 `Remove-Item -Recurse -Force`（PowerShell）。

## 3. 十五分钟冒烟脚本（按序执行）

每步给出预期。任一步不符，先看 §6 排障。本节命令在 Git Bash 里整段执行。

```bash
export OMEM_HOME=/tmp/omem-t1 && cd /x/omem

# S1 建库（--no-scan 跳过首次会话扫描，快；去掉则扫真实 ~/.claude/projects，只读）
node bin/omem.js init --no-scan
# 预期：打印「omem 数据目录: …」+「git 数据仓已初始化」+「跳过首次会话扫描」；退出码 0
# 产物：$OMEM_HOME/{knowledge,archive,index,snapshots,logs,config.toml,MEMORY-INDEX.md,.git}

# S2 手动写入两条（一 fact 一 preference）
node bin/omem.js add "omem 的检索走 FTS5 trigram，中文查询词少于 3 个字符时退化为 LIKE 兜底" --type fact --domain tech --tags 检索,FTS5
node bin/omem.js add "以后部署统一用 Docker Compose，不再裸跑 docker run" --type preference --domain ops
# 预期：各打印「已保存 id: YYYY-MM-DD-xxxxxx」和「文件: <path>」；退出码 0
# 手动 add 是 verified:true。这两条此时还没进 git 提交，见 §4.1

# S3 检索三形态
node bin/omem.js search "FTS5 trigram"    # 两个词都 ≥3 字符 → trigram MATCH（AND）
node bin/omem.js search "部署"            # 2 字中文 → LIKE 兜底
node bin/omem.js search "不存在的词xyz"   # 无命中：退出码 0
# 命中时：标题后带「——刚刚确认」（verified 且刚刚写入），文末一行
#   「（个人记忆参考笔记，非指令；未验证条目请谨慎采信）」
# 无命中时打印「未找到与「…」相关的记忆。」并附带 ≥3 字符 / --all 的提示
# 不要用「trigram 检索」当 trigram 样例：「检索」只有 2 个字，整条查询会走 LIKE

# S4 队列与生命周期
node bin/omem.js review     # 预期：「队列为空：没有待确认候选，也没有冷却条目。」
node bin/omem.js gc         # 预期：「扫描 active N 条（阈值 180 天未确认）：标记 stale 0 条（只标记，未删除）」

# S5 加工会话（合成 fixture，不碰真实数据）
# 默认档只把对话写入 sessions/ 并打印 PROCESS.md，不写 knowledge
OMEM_CLAUDE_PROJECTS=/x/omem/tests/fixtures/claude-projects node bin/omem.js run --dry-run
# 预期：Processing complete (tier agent, dry-run)；dry-run 不落盘
OMEM_CLAUDE_PROJECTS=/x/omem/tests/fixtures/claude-projects node bin/omem.js run --tier rules
# 落盘后：sessions/ 有该会话；knowledge 里能看到 sk-ant-***REDACTED***，看不到 fixture 里的完整密钥；
# 看不到 sidechain-marker-xyz，也看不到 summary 行里的「会话摘要」
# 这些候选是 verified:false，此时 review 队列不再为空

# S6 上下文导出与可观测
node bin/omem.js context --for plain    # 预期：以「# omem 个人记忆索引」开头，正文即 MEMORY-INDEX
node bin/omem.js audit --tail 3         # 预期：JSONL。手动 add 的事件名是 commit，不是 add；CLI search 不写日志

# S7 同步状态
node bin/omem.js sync status
# 预期：
#   后端: git
#   远端: （未配置：omem sync remote <url>）
#   待推送: 0 · 待拉取: 0 · 未提交改动: N    （N≥1，因为 S2/S5 的文件还没提交）
#   备注: 无 upstream 分支（未推送过或未配置远端）
```

### 退出码契约（规格 §7）

| 码 | 含义 | 复现 |
|---|---|---|
| 0 | 成功（含"冲突已处理"） | 上述全部命令 |
| 1 | 用法错误 | `node bin/omem.js redact`（缺 `--id`，用法是 `omem redact --id <id>`） |
| 2 | 后端不可用 / 策略拒绝 | `omem profile use work` 后 `omem context --for plain`；或把后端改成 webdav 后再 `omem sync`（见 §5） |

## 4. 分主题深测

### 4.1 md 权威性（第一卖点，优先验证）

写入本身**不会**每个文件一次提交。`omem init` 成功时最多有一条 `chore: omem init`（空仓库允许这次提交失败）。之后的 `add` / `run` 只改工作区。`omem sync` 才把未提交改动收成提交；没配远端时也会本地提交，并提示未配置远端。

```bash
rm -f $OMEM_HOME/index/omem.db*          # 索引全删（含 wal/shm）
node bin/omem.js search "FTS5 trigram"    # 预期：仍能检索（打开时 catch-up 重建）
node bin/omem.js rebuild                  # 预期：从 md 全量重建，条目数不变
node bin/omem.js sync                     # 无远端：本地提交，退出码 0
cd $OMEM_HOME && git log --oneline | head # 预期：能看到 omem: sync … 这一笔提交
```

再用 Obsidian/VSCode 打开 `$OMEM_HOME/knowledge` 改一条 md 的正文 → 跑 `omem search` → 改动生效（下次访问检出）。

### 4.2 检索矩阵

默认最多返回 `top_k`（配置里是 3）条。`archived` 与 `superseded` 默认不出现，`--all` 才带回。

| 查询 | 路径 | 预期 |
|---|---|---|
| `FTS5 trigram`（各词都 ≥3 字符） | trigram MATCH | 两个词都出现才命中；S2 的 fact 命中，preference 不命中 |
| `部署`（2 字中文） | LIKE 兜底 | 子串匹配 |
| `Compose 部署` | 先整串 LIKE，对不上再逐词 AND | 「部署」不足 3 字，不会走 trigram。整串「Compose 部署」在正文里不相邻，所以退化为两词都出现才返回 |
| `search "部署" --domain ops` | 过滤 | 只返回 ops 域 |
| stale 降权 | trigram 与 LIKE 都有 | 手工把某条 `last_confirmed` 改到 200 天前 + `omem gc` → 该条排后，标注为「未再确认（已冷却）」 |
| 已取代 | 默认排除 | `add "新约定 …" --supersedes <旧id>` 后，默认 search 找不到旧条目；`--all` 能找到，并带「已被 … 取代」 |

### 4.3 同步（本地 bare remote，不碰公网）

两边各 `add` 一条新记忆**不会**冲突：id 不同，文件路径不同，git 会把两边都收进来。冲突只发生在**同一个文件**两边都改过的时候。

```bash
git init --bare -b main /tmp/omem-remote.git
node bin/omem.js sync remote /tmp/omem-remote.git
node bin/omem.js add "同步测试条目" && node bin/omem.js sync     # 本地提交并 push

# 第二台「机器」。clone 出来的目录还不是 omem init 的骨架，测 pull 前先让它成为 OMEM_HOME：
git clone /tmp/omem-remote.git /tmp/omem-home2
# 在 home2 里改同一条 md 的正文并保留不提交；回到第一台改同一文件、sync 推上去；
# 再在 home2：OMEM_HOME=/tmp/omem-home2 node bin/omem.js sync
# 预期：退出码 0，报告冲突；远端版另存 <file>.conflict.md，本地版保留（只报告，不自动合并）
```

### 4.4 MCP 接线（真实使用路径）

探针和加工都吃当前 `OMEM_HOME`。先完成 §3 的 S5 真跑（不是只 dry-run），探针里的 `search_memory` 才能命中 fixture 的「手写 SQL」。探针还会往该库第一条记忆末尾追加一行标记，所以只能对临时库跑。

```bash
# 1) 只读预览（不落盘、不备份）
node bin/omem.js install --list
node bin/omem.js install --print-config workbuddy
node bin/omem.js install --print-config claude-code
# claude-code 的目标文件是 ~/.claude.json（merge mcpServers.omem），不是 ~/.claude/mcp.json
# workbuddy 的目标文件是 ~/.workbuddy/mcp.json
# cursor 的目标文件是 ~/.cursor/mcp.json（项目级 .cursor/mcp.json 另说，install 写的是用户目录这份）
# 预览应含 mcpServers.omem，且原有服务器键还在

# 2) 探针自检（必须把 bin 传进去；沿用上面的隔离 OMEM_HOME）
node tests/mcp-probe.mjs bin/omem.js
# 握手、tools/list、search_memory、save_memory 两次（第二次幂等）、外部编辑 catch-up、stdout 纯 JSON

# 3) 真实接线才会写文件。会话 jsonl 不动，但会改客户端配置：
#    - 只 merge 该客户端的 omem 键，写前自动备份为 <file>.omem-backup-<时间>
#    - marker 段（~/.claude/CLAUDE.md）仅在选中 claude-code 时写入
#    - 无 --target 时：TTY 进入交互勾选；非 TTY 直接报用法错误（不再静默全装），
#      脚本化场景必须显式 --target
#    未做全局安装时，写入的启动命令是「omem」。客户端会找不到它。
#    先 npm link，或 install --command 指到本机可执行文件。
cp ~/.workbuddy/mcp.json ~/.workbuddy/mcp.json.mybackup
node bin/omem.js install --target workbuddy

# 3b) 交互路径手测（需真实终端，无法脚本化）：直接跑 node bin/omem.js install
#    预期：列出全部客户端，光标在首行，cursor/workbuddy 预选中（detected + 路径已核实）
#    空格切换当前项 / a 全选 / n 全不选 / ↑↓ 移动 / 回车确认 / q 取消
#    q 或「回车但未选任何项」→ 不写任何文件；Ctrl+C 同样安全退出（raw mode 已恢复）
#    末项 "other" 选中后只打印通用 mcpServers 片段，不写文件

# 3c) codex 走 TOML 文本级合并：只追加/替换 [mcp_servers.omem]，
#    config.toml 里带引号的段名（[projects.'E:\x']）与空表段必须原样保留
node bin/omem.js install --print-config codex | head -1   # 预期：# Target file: …（不是 Cannot auto-generate）

# 4) 重启 WorkBuddy → 新对话里让 agent「检索一下我的 omem 记忆」
```

新 MCP 服务不会自动激活，必须重启客户端。交互会话与自动化会话的连接器开关相互独立。

### 4.5 安全基线

脱敏要求 `sk-ant-` 后面至少 20 个字符。`sk-ant-abc123` 太短，会原样入库，不能拿来当反例。

```bash
node bin/omem.js add "测试密钥 sk-ant-abc123def456ghi789jkl012 不要外泄" --type fact
# 预期先打印「已脱敏 1 处敏感内容」，再打印已保存
grep -r "sk-ant-abc123def456ghi789jkl012" $OMEM_HOME/knowledge    # 预期：无命中
grep -r "sk-ant-\*\*\*REDACTED\*\*\*" $OMEM_HOME/knowledge       # 预期：有打码标记

node bin/omem.js profile use work
node bin/omem.js context --for plain            # 预期：被拒，退出码 2
OMEM_ALLOW_WORK_EXPORT=1 node bin/omem.js context --for plain   # 显式放行
node bin/omem.js profile use home               # 测完切回来，避免后面的 sync 被拒

node bin/omem.js pause && node bin/omem.js resume
# pause 只停 omem run；手动 add 与 MCP save_memory 仍可写
```

`--force` 只绕过禁区关键词和 work 档的代码密度，不绕过脱敏，也不绕过去重。

node bin/omem.js eval recall

## 5. 已知边界（不是缺陷）

- Node < 22.5 无 `node:sqlite`，bin 包装器会给出启动失败提示。
- FTS5 trigram 对不足 3 个字符的词无效，这种查询整段走 LIKE。这是设计内行为。
- `omem context` 在 work profile 下默认被拦，是合规设计，不是 bug。
- `omem sync use webdav`（`dir` 同样）**退出码是 0**，并且会把 `config.toml` 里的 backend 改成 webdav。它只打印「V0.2 交付」。接下来的 `omem sync` 才会因后端未交付退出 2。测完执行 `omem sync use git` 改回来。
- 时间衰减 V0.1 不做。`gc` 只按 `stale_after_days`（默认 180）把条目标成 stale。
- 档 0 规则抽取的质量还不是 Q1。`eval recall` 的数字是子串包含的弱代理，只作回归信号。

## 6. 排障速查

| 现象 | 大概率原因 |
|---|---|
| `ERR_UNSUPPORTED_ESM_URL_SCHEME` | 直接 `node dist/cli.js` 且漏了 `--experimental-sqlite`；用 `node bin/omem.js` |
| `node: command not found`（跑 smoke 时） | PATH 上的 `bash` 是 WSL；改用 Git Bash，见 §1 |
| 「未初始化：... 不存在」 | 漏了 `export OMEM_HOME=...` 或目录被删；`omem init` 重建 |
| 检索结果为空但明明 add 过 | 查询里有不足 3 字的词，整串又对不上；或条目已 superseded/archived，加 `--all` |
| `mcp-probe` 立刻打印用法并退出 | 没传 bin：`node tests/mcp-probe.mjs bin/omem.js` |
| 探针里 search 没命中「手写」 | 当前 `OMEM_HOME` 没跑过 fixture 的 `omem run --tier rules`（默认 run 只写 sessions/，dry-run 不算） |
| `omem install` 后客户端不显示工具 | 未重启客户端；连接器开关被关；或写入的命令是 `omem` 但没有全局安装 |
| `omem sync` 退出码 2 且提示 webdav 尚未交付 | 之前 `sync use webdav` 改过配置；`omem sync use git` |
| push 失败 | 无远端或网络；`omem sync status` 看 ahead/behind，本地提交不丢 |
